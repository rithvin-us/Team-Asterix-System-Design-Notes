# Examples

Small illustrations of a **single point**. Short — often one diagram and a paragraph.

Not to be confused with [case studies](../04-case-studies/), which trace a whole
system end to end. The line: if it exists to explain a concept, it is an example. If
it exists to be studied as a system, it is a case study.

## By domain

| Domain | |
|---|---|
| [Automotive / robotics](automotive/) | ATV, sensors, embedded, vehicle networks |
| [Software](software/) | Backend, distributed, application systems |

Domain is a subfolder, never a top-level split — the method is the same either way.
See [CONVENTIONS.md](../CONVENTIONS.md#the-one-rule-that-matters).

## Adding one

One file, `kebab-case.md`, in the right domain folder. State at the top **which
concept it illustrates** and link to it. If it has a diagram, give it a folder with a
`diagrams/` subfolder.

Good examples are often negative: *here is a power flow drawn badly, and here is what
a reader cannot tell from it.* Those teach faster than correct ones.
